# 自律改善ログ（ビジコン向け・宮大非公式アプリ）

このドキュメントは、宮大非公式アプリをビジネスプランコンテスト向けに継続的に磨き上げる作業の記録である。
方針は一貫している。

- **学生からは一切課金しない**
- **収益源は宮崎県内企業・店舗からの協賛を主軸とする**
- **宮崎県への地域貢献という視点を持つ**
- **PWAというアーキテクチャは変更しない**
- 実装済みの部分は**デバッグ**を中心に、未実装の部分は**充実**させる

各サイクルは概ね以下の順序で行う。

1. 役割決め（何を・どのエージェントが・どの視点で見るか）
2. デバッグ（型チェック・Lint・実際にブラウザで動かして検証）
3. 実装・修正
4. サブエージェントによる客観レビュー（実データ・実市場との照合、需要検証）
5. 1に戻る

---

## サイクル1（2026-08-20）

### 役割決め
- 本体（自分）: デバッグ、機能実装、コミット・デプロイ
- サブエージェント1（`general-purpose`, バックグラウンド）: 「地域協賛モデル」の市場妥当性を実際のWeb検索で検証

### デバッグ
- `npx tsc --noEmit`: エラー0
- `npx eslint .`: エラー0（既存の軽微な警告3件のみ、変化なし）
- ローカルDocker Postgres (`miyadai-postgres`) が停止していたため起動し、`prisma migrate status` で最新化を確認
- 実ブラウザで サインアップ→ホーム→授業カルテ の一連の流れを確認、コンソールエラーなし

### 実装した機能
1. **Sponsorモデル追加**（`prisma/schema.prisma`）: 宮崎県内の企業・店舗の協賛情報（店名・カテゴリ・紹介文・学生特典・エリア・掲載期間等）を保持
2. **`/sponsors`ページ**（公開・未ログインでも閲覧可）: 「地元とつながる」というタイトルで、学生から課金しない旨と、協賛企業の一覧を表示。マイページから控えめな導線でリンク
3. **`/api/sponsors`**（公開GET）: 掲載中・期限内の協賛のみ返す
4. **`/api/admin/sponsors`（+`/[id]`）**: 既存の`issue-temp-password`と同じADMIN_SECRET Bearer認証によるCRUD。UI画面は用意せず運営がcurlで操作する運用（既存の運用方針と統一）
5. **`docs/pivot_story.md`**: THE Taling.（別のビジコンで開発した実験的アプリ）から本アプリへのピボットの経緯を、捏造データを使わず定性的事実（継続利用・複数人からの要請）に基づいて整理

### 検証
- curlでSponsorのCRUD一式（作成→管理者一覧反映→公開一覧反映→非公開化→公開一覧から消える→権限なしアクセスは401→削除）を実地確認、すべて想定通り
- ブラウザで`/sponsors`の空状態・データありの両方の表示を確認
- マイページに追加したリンク（`/sponsors`）がクリック可能な状態で存在することを確認

### デプロイ
- `main`ブランチへコミット・push（Vercelの`prisma migrate deploy && next build`により本番DBへも新テーブルが反映される）

### サブエージェントレビュー（結果待ち）
- 「地域協賛による無料学生アプリ」モデルの市場妥当性・実例・リスクを、実際のWeb検索で検証中。結果は次のサイクルの冒頭に追記する。

### 次サイクルの候補（優先度順・仮）
1. サブエージェントのレビュー結果を踏まえた協賛モデルの調整
2. 協賛枠の「表示回数（インプレッション）」を記録し、企業向けに協賛の効果を示せるようにする（協賛料の説明材料になる）
3. 授業カルテの投稿を増やすための小さな導線改善（差別化要素の強化）
4. `docs/pivot_story.md`をベースにした、ビジコン提出用プレゼンテーション資料の下書き（※これはユーザーがループを止めた後の最終成果物として作成する約束のため、通常サイクルでは着手しない）
