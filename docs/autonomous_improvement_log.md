# 自律改善ログ（ビジコン向け・宮大非公式アプリ）

このドキュメントは、宮大非公式アプリをビジネスプランコンテスト向けに継続的に磨き上げる作業の記録である。
方針は一貫している。

- **学生からは一切課金しない**
- **収益源は宮崎県内企業・店舗からの協賛を主軸とする**
- **宮崎県への地域貢献という視点を持つ**
- **PWAというアーキテクチャは変更しない**
- 実装済みの部分は**デバッグ**を中心に、未実装の部分は**充実**させる

各サイクルは概ね以下の順序で行う。

1. 役割決め（何を・どのエージェントが・どの視点で見るか）
2. デバッグ（型チェック・Lint・実際にブラウザで動かして検証）
3. 実装・修正
4. サブエージェントによる客観レビュー（実データ・実市場との照合、需要検証）
5. 1に戻る

## サイクル1（2026-08-20）

### 役割決め
- 本体（自分）: デバッグ、機能実装、コミット・デプロイ
- サブエージェント1（`general-purpose`, バックグラウンド）: 「地域協賛モデル」の市場妥当性を実際のWeb検索で検証

### デバッグ
- `npx tsc --noEmit`: エラー0
- `npx eslint .`: エラー0（既存の軽微な警告3件のみ、変化なし）
- ローカルDocker Postgres (`miyadai-postgres`) が停止していたため起動し、`prisma migrate status` で最新化を確認
- 実ブラウザで サインアップ→ホーム→授業カルテ の一連の流れを確認、コンソールエラーなし

### 実装した機能
1. **Sponsorモデル追加**（`prisma/schema.prisma`）: 宮崎県内の企業・店舗の協賛情報（店名・カテゴリ・紹介文・学生特典・エリア・掲載期間等）を保持
2. **`/sponsors`ページ**（公開・未ログインでも閲覧可）: 「地元とつながる」というタイトルで、学生から課金しない旨と、協賛企業の一覧を表示。マイページから控えめな導線でリンク
3. **`/api/sponsors`**（公開GET）: 掲載中・期限内の協賛のみ返す
4. **`/api/admin/sponsors`（+`/[id]`）**: 既存の`issue-temp-password`と同じADMIN_SECRET Bearer認証によるCRUD。UI画面は用意せず運営がcurlで操作する運用（既存の運用方針と統一）
5. **`docs/pivot_story.md`**: THE Taling.（別のビジコンで開発した実験的アプリ）から本アプリへのピボットの経緯を、捏造データを使わず定性的事実（継続利用・複数人からの要請）に基づいて整理

### 検証
- curlでSponsorのCRUD一式（作成→管理者一覧反映→公開一覧反映→非公開化→公開一覧から消える→権限なしアクセスは401→削除）を実地確認、すべて想定通り
- ブラウザで`/sponsors`の空状態・データありの両方の表示を確認
- マイページに追加したリンク（`/sponsors`）がクリック可能な状態で存在することを確認

### デプロイ
- `main`ブランチへコミット・push（Vercelの`prisma migrate deploy && next build`により本番DBへも新テーブルが反映される）

### サブエージェントレビュー（完了・実データに基づく検証結果）

Web検索による実データ検証の結果（出典付き）:

1. **既存実例**: 「ガクセイ協賛」（全国600大学5500団体登録）は存在するが、企業が学生に案件を依頼し謝礼を払う型で、宮大アプリの「店舗掲載＋学生特典」型とは別カテゴリ。近似する実例は大学生協の学生割引（190生協加盟、原資は組合費）や近大生限定クーポンなど。純粋な「協賛料収入モデル」の直接実例は少ない。
2. **宮崎県の姿勢**: 宮崎県・宮崎市は移住支援金（最大200万円）等、若者定住施策に実際に予算を割いており、行政の学生・若者施策への意欲は高いことを確認。ただし「宮崎県内企業の学生協賛」の直接実例は未確認。
3. **稼働実態**: 商店街×大学連携（経産省の事例集にも掲載）は前例として存在するが、失敗・撤退の具体データは今回の検索では見つからず。
4. **最大のリスク**: 個人・学生開発者は協賛営業（訪問・契約・特典更新管理）を継続的に回すための人的リソースが構造的に不足しがちだという指摘。開発と営業の兼務は重い。

**総合評価**: 「地域協賛モデル」自体には方向性の妥当性（商店街×大学連携、大学生協の前例）があるが、**協賛営業を学生開発者一人で回せるかが最大のリスク**。示唆として、
- 個別企業への飛び込み営業より、**行政の地域連携予算・商店街振興組合との提携**を最初の窓口にする方が現実的
- 既に導入済みの**AdSense広告収益を当面の主力**とし、地域協賛は「地域とのつながりを示すビジコン向けの独自性」「将来育てる収益源」として位置づける方が無理がない

### この結果を受けた方針修正
- 協賛モデル自体は**廃棄せず継続**するが、ビジコン資料上は「今すぐ営業して収益化する」ではなく「宮崎県・商店街振興組合等の地域連携から始める中長期の収益源」として位置づけ直す
- `docs/pivot_story.md`の収益源に関する記述を、AdSense（既存・当面の主力）＋地域協賛（中長期・地域貢献の象徴）という二層構造に更新する（次サイクルで実施）

### 次サイクルの候補（優先度順・更新済み）
1. `docs/pivot_story.md`の収益モデルの記述を、AdSense＋地域協賛の二層構造に更新
2. 協賛枠の「表示回数（インプレッション）」を記録し、将来企業向けに協賛の効果を示せるようにする
3. 授業カルテの投稿を増やすための小さな導線改善（差別化要素の強化）
4. `docs/pivot_story.md`をベースにした、ビジコン提出用プレゼンテーション資料の下書き（※これはユーザーがループを止めた後の最終成果物として作成する約束のため、通常サイクルでは着手しない）

## サイクル2（2026-08-21）

### 役割決め
- 本体（自分）: デバッグ、機能実装、コミット・デプロイ
- サブエージェント1（`general-purpose`, バックグラウンド）: 「授業カルテ」機能そのものの需要・競合・リスクを実データで検証（サイクル1は収益モデルの検証だったため、今回はプロダクトの核心機能を検証）

### デバッグ
- `npx tsc --noEmit`: エラー0
- `npx eslint .`: エラー0（既存の軽微な警告3件のみ、サイクル1から変化なし）
- ローカルDocker Postgres (`miyadai-postgres`) 稼働確認済み

### 実装した機能（サイクル1の候補2・3を実施）
1. **協賛枠のインプレッション・クリック計測**（`prisma/schema.prisma`にSponsorへ`impressionCount`/`clickCount`追加、マイグレーション`20260820165937_add_sponsor_metrics`）
   - `GET /api/sponsors`：一覧取得のたびに表示回数を加算（レスポンスをブロックしない）
   - `POST /api/sponsors/[id]/click`：「詳しく見る」リンククリック時に加算（`/sponsors`ページから呼び出し）
   - 狙い：将来、協賛企業に「実際に何回見られ、何回クリックされたか」を提示できるようにする。サイクル1のサブエージェントレビューで指摘された「協賛の効果を示せることが継続営業の鍵になる」という示唆への対応
2. **授業カルテ投稿を増やす導線改善**（`src/app/courses/[id]/page.tsx`）
   - 成績が確定した授業の詳細ページに「後輩のためにカルテへ残しませんか？」というCTAカードを追加し、カルテ投稿ページへの直接導線を設置
   - 狙い：「情報が一番出したくなる瞬間（履修が終わった直後）」に投稿を促す。授業カルテは投稿数が増えるほど価値が上がるネットワーク型の資産のため、投稿の絶対数を増やすことを優先

### 検証
- `npx prisma migrate dev`でローカルDBに適用、Prisma Clientを再生成
- curlで協賛枠を仮作成→`GET /api/sponsors`を複数回叩いて`impressionCount`が加算されることを確認→`POST /api/sponsors/[id]/click`で`clickCount`が加算されることを確認→テストデータを削除して後片付け
- ブラウザで`/sponsors`ページの表示を確認（協賛カード・特典表示とも正常）
- 授業カルテCTAはUIコード上のロジック確認（`course.grade`かつ`course.syllabusCourseId`がある場合のみ表示）で、型・Lintエラーなしを確認

### サブエージェントレビュー(完了・実データに基づく重要な検証結果)

Web検索による客観検証の結果、**重大な事実が判明した**。

- 「みんなのキャンパス」に宮崎大学専用ページが既に存在し、**2,917件の口コミが蓄積**されている（楽単・課題量・満足度ランキング等、学部/教授名別）。過去4年分の投稿があり稼働中。
- 全国区の「Penmark」（約10万件の履修者口コミ）、「すごい時間割」も競合として存在する。
- **「宮大に授業口コミのインフラがない」という当初の前提は事実として崩れている。** 授業カルテという「情報を貯める」核心機能自体は後発。
- 一方、匿名の授業口コミが抱えるリスク（教員個人への誹謗中傷、大学からの停止要請）は、他大学の一般的なSNS対応事例からも現実的な課題として確認された。

**総合評価**: 需要不在がリスクなのではなく、①後発としての差別化を示せるか、②匿名投稿の誹謗中傷リスクへの対策、の2点が最大の課題。

### この結果を受けた方針修正・実装（サイクル3で対応）
1. **`docs/pivot_story.md`を実データに基づいて更新**: 「情報インフラがないところに作る」という当初の物語を撤回し、差別化を「日常使いツールへの組み込み」「シラバス連携」「安全性（通報・自動非表示）」「学生無課金+地域協賛という事業モデル」に再定義した（新設「6. 客観的な競合分析」節）
2. **授業カルテの通報・自動非表示機能を実装**（`prisma/schema.prisma`にCourseKarteへ`reportCount`/`hidden`追加、マイグレーション`20260820170307_add_karte_report_moderation`）
   - `POST /api/karte/[id]/report`: IPレート制限付きの通報エンドポイント。3件通報が集まると自動的に`hidden: true`にし、`GET /api/karte`の一覧から除外する
   - `src/app/karte/[id]/page.tsx`「みんなの声」タブに「不適切な内容を報告」ボタンを追加
   - 狙い: サブエージェントが指摘した「匿名投稿による誹謗中傷リスク」への具体的な対策。運営が常時監視できない個人開発体制でも、被害拡大を自動的に抑える

### 検証（サイクル3分）
- `npx tsc --noEmit` / `npx eslint`: エラー0
- ローカルDBに手動でテスト用授業・カルテを作成し、テストアカウントでログインした状態で3回通報 → 4回目の一覧取得で該当カルテが除外されることを確認。テストデータは全て削除して後片付け
- 開発サーバーのPrisma Clientキャッシュが古いままだった問題に気づき、サーバー再起動で解消（マイグレーション後はdevサーバー再起動が必要、という運用上の教訓）

### 次サイクルの候補（優先度順）
1. 協賛管理者向けに、蓄積された`impressionCount`/`clickCount`を確認しやすくする（現状は管理APIのJSONレスポンスのみ）
2. 「みんなのキャンパス」等の既存サービスからの乗り換え理由を具体化する機能（例: 時間割・出席管理と一体化した投稿導線をさらに強化する、シラバス変更検知の可視性を上げる）
3. `docs/pivot_story.md`をベースにしたビジコン提出用プレゼンテーション資料の下書き（引き続き、ユーザーがループを止めた後の最終成果物として着手）
